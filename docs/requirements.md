# 菇菇提醒 App — 需求文件

> 給實作者的前置說明：本文件作者的背景是前後端工程師，非 iOS 開發者。
> 請在實作過程中，對 iOS 專有機制附上簡短說明，不要預設讀者熟悉 Apple 生態系。

---

## 1. 背景與目標

### 使用情境

使用者是 Pikmin Bloom 玩家。遊戲中地圖上的「菇」被打爆後，**約 5 分鐘會在原地重生**。重生後的菇有名額限制（前 5 名免費參戰），所以必須在重生的當下就人在現場。

目前的做法是用 iOS 內建時鐘手動設鬧鐘，並手動打字標註是哪一顆菇。痛點有二：

1. **打字命名太慢** — 現場操作時沒空打字
2. **周遭菇太多** — 同一區域有多顆菇，光看鬧鐘標籤分不出來是哪顆

### 設計核心

- 把「登記一顆菇」的操作壓縮到 **2～3 個 tap，零打字**
- 菇的身分靠**「地點群組 + 預先建立的清單」**辨識，不靠即時輸入
- 提醒時間**自動計算**，使用者只需輸入眼睛看到的剩餘時間

### 明確排除的功能

以下功能經討論後決定**不做**，請勿自行加入：

| 項目 | 排除原因 |
|---|---|
| 菇的種類 / 等級記錄 | 重生後的菇種無法預測，記錄無意義 |
| 每日免費次數（扣打）統計 | 一天僅 3 次，使用者自行掌握即可 |
| 任何遊戲資料的自動抓取 | Pikmin Bloom 無公開 API，逆向工程違反服務條款 |
| 帳號系統 / 雲端同步 | 單機單人使用，且免費開發者帳號無法使用 iCloud |

## 2. 技術約束（重要，請先讀完再開始）

本專案使用 **免費的 Apple Developer 帳號（Personal Team）**，這帶來數個硬性限制，會直接影響架構決策。

### 2.1 不可使用任何需要 entitlement 的能力

免費帳號無法簽署需要特殊授權的功能。以下**一律禁止使用**：

- ❌ **App Groups** — 這是最關鍵的一條，見 2.2
- ❌ Push Notifications（遠端推播）
- ❌ iCloud / CloudKit
- ❌ Sign in with Apple
- ❌ Associated Domains

> 白話說明：iOS 上某些功能需要向 Apple 「登記」才能使用，免費帳號沒有登記權限。
> 如果專案設定裡加了這些能力，App 會直接無法安裝到手機上。

### 2.2 【架構紅線】Widget 與主 App 不可共用資料庫

**背景說明**：在 iOS 上，桌面小工具（Widget）和鎖定畫面的即時狀態列（Live Activity）
是跑在**獨立的 process** 裡的，跟主 App 不是同一個程式。一般做法是用 App Groups
開一個共用的檔案區讓兩邊都能讀寫 —— 但免費帳號不能用 App Groups。

**因此必須遵守**：

- Live Activity 顯示所需的**全部資料**，必須在建立/更新的當下，
  透過 `ActivityAttributes` 與 `ContentState` 一次打包傳遞完成
- Widget extension **不可以**嘗試讀取主 App 的資料庫
- 不可在 entitlements 檔案中出現任何 App Group 設定

> 用後端概念類比：把它想成 Widget 是一個沒有資料庫連線權限的無狀態服務，
> 只能吃你 request 時塞給它的 payload。

### 2.3 倒數計時的實作方式

倒數**不可以**用背景輪詢或定時推送更新去實作。

請使用 SwiftUI 的 `Text(timerInterval:countsDown:)`。這個元件只要給它一個
「結束時間」，就會在畫面上自己逐秒跑動，完全不需要程式在背景做任何事。

因為每一筆提醒的結束時間在建立當下就已經算出來了，這個做法可以做到
**零背景作業、零耗電**，同時也自然繞開了 2.2 的限制。

### 2.4 通知的可靠度 ⚠️ 需要優先驗證

提前量可能只有 15 秒，所以通知必須準時響，不能被系統延遲或被「專注模式」擋掉。

理想做法是把通知設為 **Time Sensitive（時效性通知）**，但這個功能**可能**需要
entitlement，免費帳號或許無法使用。

**請在專案開始的第一天，先寫一個最小測試驗證這一點**，不要等功能都寫完才發現。

- 若可用 → 使用 Time Sensitive
- 若不可用 → 使用一般通知，並在 App 的說明頁引導使用者手動將本 App
  加入「專注模式」的允許清單（此做法不需要任何 entitlement，效果相同）

### 2.5 其他

- App ID 的設定每 7 天僅能修改 10 次 → **Bundle ID 與專案能力設定請一開始就定案**，
  避免反覆調整導致無法建置
- provisioning profile 每 7 天過期，需重新從 Xcode 安裝（使用者已知悉並接受）
- 資料全部存在本機，不需要考慮同步或衝突處理

## 3. 資料模型

三張表，本機儲存（建議 SwiftData，等同於本機 SQLite 的 ORM）。

### Group（地點群組）

代表一個地理區域，例如「中山路口」。

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | UUID | PK |
| name | String | 群組名稱，可編輯 |
| latitude | Double | 建立當下的緯度 |
| longitude | Double | 建立當下的經度 |
| radius | Double | 判定半徑，預設 80 公尺 |
| createdAt | Date | |

### Mushroom（菇）

隸屬於某個群組的一顆菇。

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | UUID | PK |
| groupId | UUID | FK → Group |
| name | String | 例如「7-11 門口」「天橋下」 |
| useCount | Int | 使用次數，用於清單排序 |
| lastUsedAt | Date? | |

### Timer（計時）

一筆進行中的提醒。

| 欄位 | 型別 | 說明 |
|---|---|---|
| id | UUID | PK |
| mushroomId | UUID | FK → Mushroom |
| createdAt | Date | 登記當下的時間 |
| remainingSeconds | Int | 使用者輸入的剩餘秒數 |
| leadSeconds | Int | 本筆使用的提前量（快照，不要即時讀設定值） |
| fireAt | Date | 計算後的提醒時間，見 §4 |
| status | Enum | active / fired / completed / cancelled |

> 注意 `leadSeconds` 要存快照。使用者之後改了全域預設值，不應影響已建立的計時。

### Settings（全域設定）

| 項目 | 預設值 | 說明 |
|---|---|---|
| respawnSeconds | 300 | 菇的重生時間（5 分鐘），做成可調整，以防官方調整數值 |
| defaultLeadSeconds | 15 | 預設提前量 |

---

## 4. 核心計算邏輯

```
fireAt = now + remainingSeconds + respawnSeconds - leadSeconds
```

**範例**：菇還剩 2:30，重生 5:00，提前 15 秒
→ 150 + 300 - 15 = 435 秒 = **7:15 後提醒**

邊界處理：

- 若計算結果 ≤ 現在時間，立即提示使用者「時間已過」，不建立計時
- `remainingSeconds` 允許為 0（代表「剛爆」）
- 所有計算以秒為單位，避免浮點誤差

## 5. 功能需求

### 5.1 主畫面

**上半部 — 進行中的計時清單**

- 依 `fireAt` 由近到遠排序
- 每筆顯示：菇名稱、所屬群組、倒數時間（自動逐秒跑動）
- 左滑可取消該筆計時
- 空狀態時顯示引導文字

**下半部 — 快速登記區**

- 頂端顯示目前 GPS 判定的群組名稱
  - 旁邊放一個切換按鈕，可手動改選鄰近的其他群組（**必要**，因為市區 GPS
    誤差可達 10～30 公尺，自動判定不一定準）
  - 若不在任何已知群組範圍內 → 顯示「建立新群組」
- 下方列出該群組的菇清單，**依 `useCount` 由高到低排序**
- 清單末端固定一個「＋ 新增菇」

### 5.2 登記流程

1. 在主畫面點選一顆菇
2. 跳出剩餘時間輸入介面：
   - 數字鍵盤輸入，輸入「230」自動解讀為 2:30
   - 提供「剛爆」按鈕（等同輸入 0）
   - **即時顯示計算結果**：「7:15 後提醒 · 21:43:20」讓使用者確認
   - 提前量微調：`−5s` / `+5s` 兩顆按鈕，預設帶入全域設定值
3. 確認 → 建立 Timer、排定通知、啟動 Live Activity

整個流程應可在 2～3 個 tap 內完成，**過程中不需要任何打字**。

### 5.3 群組自動辨識

- App 進入前景時，取得一次目前位置（不需要背景定位權限）
- 找出距離最近且在 `radius` 內的 Group
- 建立新群組時，用反向地理編碼（把座標轉成地址/地標名稱）產生預設名稱，
  使用者可直接採用或改寫
- **位置權限僅需「使用 App 期間」**，不要要求「永遠允許」

### 5.4 通知

- 使用本機通知（不需要伺服器）
- 通知內容：`【中山路口】7-11 門口 的菇要重生了`
- 通知動作按鈕：
  - 「已完成」→ 將 Timer 標記為 completed
  - 「延後 1 分鐘」→ 重新排定
- 依 §2.4 的驗證結果決定是否使用 Time Sensitive

### 5.5 Live Activity（鎖定畫面 / 動態島）

> 白話說明：Live Activity 是顯示在鎖定畫面上、以及 iPhone 螢幕上方
> 「動態島」區域的即時狀態卡片，例如叫車 App 顯示司機還有幾分鐘到。

**關鍵限制：動態島同時只能顯示一個 Live Activity。**

因此**不可以**一筆計時開一個 Live Activity。正確做法：

- 全程**只維持一個** Live Activity
- 內容永遠顯示**最快到期的那一筆**
- 附帶顯示還有幾筆在排隊（例如「+2」）
- 當最快的那筆倒數結束，自動更新內容為下一筆
- 全部計時結束時，結束 Live Activity

需實作的四種版面：

| 版面 | 內容 |
|---|---|
| Compact leading | 菇 icon |
| Compact trailing | 倒數時間 |
| Minimal | 倒數時間 |
| Expanded | 菇名稱 + 群組 + 倒數 + 排隊筆數 |

倒數一律使用 `Text(timerInterval:)`（見 §2.3）。

### 5.6 App Intents（捷徑整合）

> 白話說明：App Intents 可以想成是「把 App 的功能開放成 API endpoint」，
> 開放之後 iOS 系統的捷徑 App、Siri、動作按鈕、控制中心都可以呼叫它。

**這是本專案價值最高的部分，請確保實作完整。**

需要開放的 Intent：

| Intent | 參數 | 行為 |
|---|---|---|
| `LogMushroom` | 菇（可選）、剩餘時間（可選） | 建立一筆計時 |
| `QuickLogHere` | 剩餘時間 | 用目前群組中最常用的那顆菇建立計時 |

**設計要點**：

- `LogMushroom` 的參數必須可以**預先綁定**。這樣使用者可以針對常打的菇各做一個
  捷徑放到桌面，達成「一個 tap 完成登記，App 完全不用開啟」
- 這些 Intent 執行時**不需要 GPS、不需要開啟 App**，因為菇是預先指定的
- 菇的參數要提供選項清單，讓使用者在捷徑 App 裡是用選的，不是打字

開放之後自動可用於：捷徑 App、Siri 語音、動作按鈕（iPhone 15 Pro 以上）、
背面輕點（透過捷徑自動化）、控制中心、鎖定畫面。

### 5.7 互動式桌面小工具

> 白話說明：iOS 17 之後，桌面小工具上的按鈕可以直接執行動作，不需要開啟 App。

- 顯示目前群組中最常用的 2～3 顆菇，每顆一顆按鈕
- 按下 → 直接以「剛爆」（剩餘時間 0）建立計時
- 這預期會成為使用者最主要的入口，因為速度最快

由於 §2.2 的限制，小工具無法讀取資料庫來動態決定要顯示哪些菇。
**請採用**：主 App 每次更新資料時，主動將「要顯示的菇清單」推送給小工具
（透過 WidgetKit 的 timeline 機制），小工具本身不做任何資料查詢。

### 5.8 資料管理

- 群組與菇的 CRUD 介面
- 刪除群組時，一併處理其下的菇（需二次確認）
- JSON 匯出 / 匯入（累積的群組與菇清單是本 App 最有價值的資產）

## 6. 開發順序建議

### 第 0 階段：先驗證（務必最先做）

1. 建立空專案，確認免費帳號可以順利安裝到實機
2. **驗證 Time Sensitive 通知是否可用**（見 §2.4）
3. 驗證 Live Activity 在不使用 App Groups 的情況下可正常運作

這三項會影響後續架構，請先確認再往下走。

### 第 1 階段：可用的 MVP

資料模型 → 群組/菇的 CRUD → 剩餘時間輸入 → 計算 → 本機通知 → 主畫面清單

**完成這一階段，App 就已經明顯優於內建時鐘了。**

### 第 2 階段：降低操作摩擦

GPS 群組自動辨識 → App Intents → 互動式桌面小工具

### 第 3 階段：體驗優化

Live Activity / 動態島 → JSON 匯出匯入 → 通知動作按鈕

## 7. 非功能性需求

- **最低支援版本**：iOS 17.0（互動式小工具的需求）
- **單手可操作**：所有主要操作按鈕須位於畫面下半部（使用情境是邊走邊用）
- **戶外可讀性**：對比度要夠，倒數數字要大
- **離線運作**：除反向地理編碼外，全部功能不依賴網路
- **省電**：不使用背景定位、不使用背景輪詢
